## R02：布局、精度与边界验证

```bash
ssh Server-Internet 'cd /data/user4/tongleiwen/minimind-ep-grouped-baseline-20261007/stage02 && RUN_NAME=R02_verification bash run_contract.sh'
```

脚本激活已确认的 venv，并检查 GPU 1 空闲后运行验证。实际步骤：

1. 从 36 个真实 MLP 回放恢复分组输入和全局专家编号；用服务器原 FeedForward 与原 checkpoint 计算，与采集输出位级对拍。
2. 按 local_expert_ids 堆叠 FP32 权重，转换 BF16，转置成连续 [E,K,N]；转换后的每个元素必须与原权重 BF16 转换一致。
3. 对比独立 gate/up/down 投影及完整 MLP；逐元素检查 atol=0.02、rtol=0.02，同时记录是否位级一致、最大绝对误差、RMS 与参考 RMS。
4. 三组 N/K × 11 组专家分配 × BF16/FP16，共 66 个合成参考检查；使用舍入后的低精度输入/权重、关闭 TF32 的 FP32 matmul 作为参考。
5. 37 组元数据边界检查，包含 0/1/31/33/65/129 行、空专家、原 E=16/M=2048 分配，以及大 M 元数据。

输出 contract_verification.json、运行脚本快照和 gpu_after.csv。返回码为 0 且 status=passed 为通过；本轮不证明 kernel9 或模型接入已经通过。

## R02 结果与 R03 调整
权重元素还原完全一致，但矩阵布局改变后的 PyTorch 运算存在非位级差异。只用逐元素 atol/rtol 不足以描述整体误差；增加相对 RMS 限制，BF16≤0.5%、FP16≤0.1%，同时保留原逐元素检查。

GPU Tile 前缀可能重复，例如空专家不增加任务数。增加 right=True 的设备前缀查找验证，逐项检查任务对应专家合法、行/列 Tile 有效，且每个有效任务恰好对应一个 Tile。大于 65536 行的元数据案例只检查前缀与容量，不生成巨大任务数组。

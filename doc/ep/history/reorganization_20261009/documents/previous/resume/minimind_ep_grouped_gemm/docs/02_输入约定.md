# 02 输入约定

## 目的
把实际 MiniMind-EP 专家输入转换为明确的 kernel9 计算契约，使算子、PyTorch 接口和模型接入使用同一套形状、精度和专家顺序，避免接入时再改变优化目标。

## 执行方案
1. 审核基线 160 个层/Rank 记录，核实实际 dtype、stride、专家顺序与 M 范围。
2. 用服务器原 FeedForward、原 checkpoint 和 36 个真实 MLP 输入回放验证参考结果。
3. 将 FP32 权重一次性转换为 BF16，再转置为连续 `[E,K,N]`；验证还原后的权重值与原权重转换完全一致，比较各投影与完整 MLP 输出。
4. 在 GPU 上构造 int64 counts、exclusive offsets 和输出 Tile 前缀；检查空专家、零总 M、集中分配、尾块和调度容量上界。
5. 用三组 N/K、两种输入精度验证布局与计算语义；大 M 仅验证元数据时单独标记。按结果确定权重缓存生命周期和阶段 03/04 的边界。

## 计算契约
下列为阶段 03/04 的实现约定。本阶段使用 PyTorch 参考验证；自定义 API 已在 [阶段 04](04_PyTorch接口.md) 注册并完成接口验收。

拟定调用：`torch.ops.my_cuda_kernels.grouped_gemm(x, packed_b, counts) -> y`。

| 参数 | 约定 |
| --- | --- |
| `x` | CUDA 连续 `[M,K]`，BF16 或 FP16，按本地专家顺序排列 |
| `packed_b` | CUDA 连续 `[E,K,N]`，与 x 同设备、同精度；从模型 `[E,N,K]` 权重转换得到 |
| `counts` | CUDA 连续 int64 `[E]`，每项非负，sum(counts)=M；与 x 同设备 |
| `y` | 新分配 CUDA 连续 `[M,N]`，与 x 同精度，保持输入分组顺序 |
| 计算 | 第 e 组 `y[offset_e:offset_(e+1)] = x[offset_e:offset_(e+1)] @ packed_b[e]`，FP32 累加后转换为输出精度 |
| 支持形状 | `(K,N)=(768,2432)、(2432,768)、(1024,1024)`；同一次调用各专家共同 N/K |
| 专家数 | 首版目标 1≤E≤16；实测 E=1/2/16，模型本地 E=2，原算子验证 E=16 |
| M | 不要求固定总数或固定分配，允许 0、空专家和任意行尾块；首版索引上限 M≤2^31−1，分配受显存限制 |
| 执行 | 仅推理前向，使用调用方当前 CUDA stream，无隐式主机同步；不包含 bias、激活、通信、排序和路由加权 |

GPU 上的本地专家编号 0/1 与 Rank 0 的全局专家 0/1、Rank 1 的全局专家 2/3 对应。权重堆叠必须遵循 `local_expert_ids`，不能按字符串排序推断专家顺序。

## 元数据与边界
由 GPU counts 生成 exclusive offsets `[E+1]` 和专家 Tile 数前缀 `[E+1]`，均用 int64。未来 launcher 的地址/容量计算使用 64 位；本轮接近 int32 上限的测试仅验证元数据，不代表分配或完整 GEMM 已验证。

候选 BM=32、BN=128 时，实际任务数为 `sum(ceil(M_i/32))*ceil(N/128)`。总 M 已知时，可在 CPU 上从张量 shape 得到固定容量上界 `(ceil(M/32)+E−1)*ceil(N/128)`，无需读取 GPU 上的实际 Tile 总数；越界任务在设备上退出。M=0 时直接返回 `[0,N]`，不启动计算。该容量方案用于首版，后续与 persistent 调度同条件比较。

正常调用只检查 shape、dtype、device、contiguous 等主机可知属性。counts 的数值合法性是调用契约；调试验证允许同步检查其非负与总和，并明确排除在性能计时外。集成时 counts 来自合法 GPU 计数流程，不把 `.tolist()` 放入新增算子的热路径。现有 EP 的通信 splits、bincount 等同步是否消除，仍需单独验证。

## 精度与权重缓存
模型参数保留 FP32；新后端在装载权重后一次性执行 BF16 转换和转置。FP16 用于算子回归，不能把 BF16 模型静默改成 FP16。暂不把 gate/up 合并成一次宽 GEMM，保留三个投影与原激活顺序，降低首轮验证变量。

每个 Rank、每层、每个投影分别缓存连续 packed_b。缓存建立在模型 checkpoint 装载完成、eval 状态及 device/dtype 已确定之后；由适配器显式持有和管理，不在每次 forward 转置或转换。重新加载/更新参数、迁移设备、改变精度、改变专家映射或进入训练时，显式失效并重建或切换原后端。首版禁止在权重变动后继续复用旧缓存，不依赖 inference tensor 的版本号追踪。

首版不融合激活：gate/up 输出按输入精度保存，使用原 PyTorch SiLU 和乘法，再调用 down GEMM；不能省略中间舍入并把结果当成同一参考。后续 kernel9 对照舍入后的 BF16/FP16 输入和权重，以 FP32/CPU double 参考检查累加；舍入顺序改变可能导致非位级一致。

## 结果
状态：已完成，2026年10月7日。160 条输入审核、36 个真实 MLP 回放、216 个投影、66 个合成参考及 37 个元数据案例通过。转换布局的 36 个 MLP 中 26 个位级一致；最大相对 RMS 为 0.2675%，差异及适用范围详见结果。每个 Rank 的权重缓存增加 171 MiB。

# MiniMind-EP Grouped GEMM 实践安排

## 目的
把独立算子连接到真实专家前向，建立“测量问题 → 设计实现 → 正确性验证 → 整体效果 → 调整复测”的路径。

## 目录
- `docs/`：目的、执行方案、结果摘要、调整闭环。
- `commands/`：实际主机、绝对工作目录、环境、版本、完整命令、输出与通过条件。
- `results/`：每轮实测数据与结论；日志、JSON、trace、图可放在对应阶段的子目录。

保持三个一级子文件夹。阶段三篇 Markdown 使用同名编号互相链接。未执行阶段明确标注待执行。

## 范围
首轮以现有模型推理前向为目标，先测基线，再按真实形状确定 kernel9。训练反向、激活融合、CUDA Graph 全链路是后续独立范围。

## 每轮闭环
1. 写清证据、问题与可验证假设。
2. 指令篇追加 R01/R02 等轮次，记录可直接执行的完整命令，确认脚本已实际存在。
3. 结果篇使用同一轮编号，记录完成状态、实际数据和对应证据。
4. 说明篇更新结果摘要、假设判断、调整原因和复测结论。
5. 保留历史轮次，明确最新结论来自哪些轮次，阶段通过后推进依赖它的工作。

## 测量规则
正式计时、预热、首次编译和 profiler 分开；记录 dtype、形状、专家分布、GPU、版本、样本数和计时范围。分别测纯计算与完整调用。实际模型路由与人工压力测试分别标注。失败和退化如实保留。

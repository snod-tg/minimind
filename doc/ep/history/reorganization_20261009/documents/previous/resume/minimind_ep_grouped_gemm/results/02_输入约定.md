# 02 输入约定：结果

## 目的
验证实际模型到动态 Grouped GEMM 的形状、精度、权重布局和元数据约定。状态：已完成，2026年10月7日。这里的计算由 PyTorch 参考实现执行，kernel9 和新 API 尚未实现；没有新增算子性能结果。

## 执行方案与环境
[精确执行指令](../commands/02_输入约定.md) · [完整契约](../docs/02_输入约定.md) · [环境](../测试环境.md)。

Server-Internet、物理 GPU 1、RTX 4090D，TileLang venv Python 3.13.5、PyTorch 2.9.0+cu128。使用 R04 的同一源码、checkpoint 和真实 MLP 输入。TF32 关闭；参考原 FeedForward 使用 FP32 参数与 BF16 autocast，转换布局的显式低精度参考在 autocast 外执行。未修改生产模型，验证进程退出后 GPU 1 恢复 24 MiB 空闲水平。

## R01：实际输入审核
160 个层/Rank 记录通过 dtype、stride、counts 总和检查。模型输入 BF16、参数 FP32、输入 stride=[768,1]；本地总 M=0～22463，单专家 M=0～12526。记录中空专家出现 24 次、零接收 Rank 出现 4 次，均为跨负载/层/Rank 的观察次数。

Rank 0 的本地顺序对应全局专家 [0,1]，Rank 1 对应 [2,3]；两个投影形状为 K=768/N=2432 与 K=2432/N=768。

## R02 与 R03：布局和精度
36 个原 FeedForward 回放与 R04 采集输出全部位级一致；普通 F.linear 参考也全部一致。转换后的权重还原回 [E,N,K] 时，与原 FP32 参数转换到 BF16 的结果逐元素完全相等。

以下表采用 R03 严格复测数据：

| 检查 | 数量 | 位级一致 | 最大绝对误差 | 最大相对 RMS |
| --- | ---: | ---: | ---: | ---: |
| 真实完整 MLP | 36 | 26 | 0.062500 | 0.2675% |
| 真实单投影 | 216 | 202 | 0.062500 | 0.3198% |
| torch.bfloat16 | 33 | 18 | 0.015625 | 0.2851% |
| torch.float16 | 33 | 13 | 0.001953 | 0.0341% |

所有项目满足逐元素 atol=0.02、rtol=0.02，同时相对 RMS≤0.5%（BF16）或≤0.1%（FP16）。相对 RMS 为误差 RMS / 参考输出 RMS；空输出记 0。阈值用于本阶段参考路径筛查，不能替代后续 CPU double 抽查、sanitizer 或整体模型验证。

10 个转换布局 MLP 不是位级一致。权重数值转换已验证一致，但不同矩阵布局可能选择不同底层算法和舍入路径；本轮没有证实差异的唯一原因，也不宣称真实模型输出保持位级一致。

真实 MLP 数值回放覆盖本地总 M 至 5628、单专家 M 至 3069。总 M=22463 的大 Prefill 目前完成 counts 审核，未在本阶段执行对应 MLP 数值回放；阶段 03/05 需要补齐大 M 计算验证。

## 动态元数据与调度映射
37 个案例全部通过，包含三组 N/K 下的 11 种分配及另外 4 组大 M 元数据。覆盖 E=1/2/16、M=0、空专家、1 行、31/33/65/129 行尾块、集中分配及原 E=16/M=2048 分配。

counts、exclusive offsets、Tile 前缀均为 GPU int64。M≤65536 的案例额外枚举全部有效任务，验证使用 right=True 查找能跳过空专家的重复前缀、专家与行/列 Tile 合法、任务映射完整。测试同时核对固定 grid 容量上界；超出有效任务数的容量由未来 kernel 判定并退出。

M=32769、65536、2^31−1 的压力案例明确为元数据测试；没有分配对应规模的矩阵，也没有证明 kernel9 的索引或内存访问安全。验证脚本中的 `.tolist()` 和断言同步仅用于检查，未来算子热路径不采用该参考代码的 CPU 同步方式。

## 权重缓存成本与约定
本地 E=2、三个投影的低精度连续缓存合计 22413312 字节，即每层 21.375 MiB；8 层额外占用每个 Rank 171 MiB，原 FP32 模型参数继续保留。

36 次转换/转置初始化 wall time 的中位数 0.246 ms，范围 0.233～8.638 ms。包含转换、分配、转置和同步，未隔离冷启动；只说明一次性准备成本，不能用于推算算子吞吐或模型加速。

首版在加载 checkpoint、eval 和设备/精度确定后显式建立缓存。参数更新、重新加载、设备或精度迁移、专家映射变化均使缓存失效；进入训练切换原实现。缓存管理代码在阶段 04/06 实现，本阶段确定规则。
